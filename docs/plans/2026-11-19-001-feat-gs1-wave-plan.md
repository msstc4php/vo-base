**Goal:** The `vo-base` additions that the new packages need, released as `vo-base` and `vo-base-doctrine` 1.2.0.
Then the GS1 package and its Doctrine bridge: identification keys, element strings, Digital Link, EPC URNs,
medical-device UDI and NDC, Russian and EU marking codes, released as 0.1.0.

**Architecture:** Every value object is a string value object (`AbstractStringValueObject`), including the
composite ones (element string, UDI, marking code). Their canonical string is the encoded content, so
`ValueObjectMapper` and every bridge handle them with no codec. Two kinds of shared code:
- check-digit algorithms live in `Internal\` helpers;
- the GS1 Application Identifier table is generated from the GS1 Barcode Syntax Dictionary, not typed by hand.

**Tech Stack:** PHP 8.4, `msstc4php/vo-base ^1.2`, PHPUnit, PHPStan max, Infection.

**Spec:** `vo-base/docs/brainstorms/2026-11-19-identifiers-and-codes-requirements.md`. Where this plan says nothing,
the conventions of `vo-documents` apply, as its plans 1-4 fixed them (`vo-documents/docs/plans/`).

## Global Constraints

- The owner's source rule (spec, "Scope"). A check digit or a structural rule is enforced only when quoted from an
  official source: GS1's own standards, a regulator's act, or an issuing agency's publication. Otherwise the class
  checks the format only, and the README's "format only" list gives the reason.
- Never refuse a value that is still valid. Old forms still in circulation are accepted.
- Registry-backed data (GS1 prefixes, company-prefix lengths) is used only to decode, never to refuse (spec). A
  well-formed value outside the table decodes as unknown.
- `__toString()` / `jsonSerialize()` give the full value. `masked()` (vo-base `Contract\Maskable`) only on sensitive
  values. None in this wave: GS1 keys, UDI and marking codes are not personal data.
- No exception message contains the input or any part of it. Messages give the type name and the length or the
  reason. Never call `InvalidValueObjectException::excerpt()` in the new packages. `vo-base` keeps its own convention.
- A factory never picks a type silently. A value that fits several types throws vo-base
  `Exception\AmbiguousValueException` listing the candidates.
- Every class cites its source with `@link`. Tests use the source's own examples where it has them.
- New packages:
  - `msstc4php/vo-gs1`: namespace `MSSTC4PHP\ValueObject\Gs1\`; `require`: `php >=8.4`, `msstc4php/vo-base ^1.2`.
  - `msstc4php/vo-gs1-doctrine`: namespace `MSSTC4PHP\ValueObject\Gs1\Doctrine\`; `require`: `msstc4php/vo-gs1`,
    `msstc4php/vo-base-doctrine ^1.2`.

## Decisions this plan makes

- **`vo-base` 1.2.0:**
  - `Contract\Maskable` (`masked(): non-empty-string`).
  - `Exception\AmbiguousValueException extends InvalidValueObjectException`: constructor `(non-empty-string $type,
    non-empty-list<class-string<ValueObject>> $candidates)`, accessor `candidates()`. The message names the type and
    the candidates' short names, never the input.
  - `I18n\CurrencyCode::numeric(): ?string` (three digits, or null for codes without one) and `static
    fromNumeric(string): self`. Both are generated by `tools/generate-iso-enums.php` from the brick/money ISO table.
    A numeric code shared by a current and a withdrawn currency resolves to the current one.
  - `Network\Eui64` (64-bit, canonical lowercase colon form like `MacAddress`) and `Network\Oui` (24-bit, canonical
    `aa:bb:cc`). `MacAddress::oui(): Oui` and `Eui64::oui(): Oui`.
  - `vo-documents` adopts `Maskable` and `AmbiguousValueException` in its MRZ release (wave 3), not here.
  - The spec leaves the per-country IBAN structure to planning: it goes to the wave-2 plan, together with the
    `CreditCardNumber` deprecation, because both are finance.
- **`vo-base-doctrine` 1.2.0:** ORM and ODM types `eui64` and `oui`, named and registered as the existing types are.
- **Doctrine type names in the bridge:** `gs1_<snake_name>` (`gs1_gtin`, `gs1_element_string`,
  `gs1_ru_marking_code`). Column length = the class's maximum length.
- **AI table:** `tools/generate-ai-table.php` reads a pinned revision of `gs1-syntax-dictionary.txt`
  (https://github.com/gs1/gs1-syntax-dictionary, recorded in the generated file's header) and writes
  `src/Internal/AiTable.php`: each AI's data format, FNC1 requirement, linters, and the `req` / `ex` association
  rules. The licence is checked first: if it allows redistribution, the package carries `NOTICE`; if not, the table
  is generated from the AI table of the GS1 General Specifications instead. Updates of the table are minor releases.
- **Exceptions:**
  - one family per area in `Gs1\Exception\`: `InvalidIdentificationKeyException`,
    `InvalidElementStringException`, `InvalidDigitalLinkException`, `InvalidEpcUriException`,
    `InvalidUdiException`, `InvalidMarkingCodeException`;
  - all of them extend vo-base `InvalidValueObjectException`.
- **GTIN canonical form:** the 14-digit form, as GS1 prescribes for storing GTINs in databases (to be quoted from the
  General Specifications in `GS1.md`; if the quote is not there, the form given is kept and equality compares the
  14-digit form). `format(): GtinFormat` (`Gtin8|Gtin12|Gtin13|Gtin14`) follows GS1's own rule for telling the
  formats apart. Accessors: `asGtin13(): ?string`, `asGtin12(): ?string`, `asGtin8(): ?string`.
- **Element string canonical form:** the bracketed form `(01)09506000134352(17)201225(10)ABC123` with a literal `(`
  in data escaped as `\(`, as the GS1 Barcode Syntax Engine does. Input is also accepted:
  - unbracketed, with FNC1 as GS U+001D or `^`;
  - optionally after a symbology identifier (`]C1`, `]d2`, `]Q3`, `]e0`, `]J1`).

  `toBarcodeData(): string` gives the unbracketed form with GS separators placed by the table's FNC1 rule.
- **Dates in element strings:**
  - `YYMMDD` with `DD = 00` means the last day of the month, as GS1 states;
  - the century comes from GS1's sliding window, relative to an explicit `DateTimeImmutable $today` argument
    (default: now, UTC), so a stored value never changes meaning.

  The result is a `DateTimeImmutable` at 00:00:00 UTC.
- **Company prefix:** keys do not decode the GS1 Company Prefix: its length is a registry fact. `fromParts(string
  $companyPrefix, string $reference)` builds a key and computes the check digit. `gs1Prefix(): Gs1Prefix` decodes
  the 3-digit prefix range from GS1's published prefix list:
  - which GS1 Member Organisation;
  - restricted circulation (`02`, `04`, `20`-`29`);
  - coupons;
  - ISBN (`978`/`979`), ISSN (`977`);
  - unknown.
- **UDI:** one class per issuing agency, all implementing `Udi\Udi` (`deviceIdentifier(): string`,
  `issuingAgency(): IssuingAgency`):
  - `Udi\Gs1Udi`, built on `ElementString`, requires AI (01);
  - `Udi\HibcUdi`: HIBC LIC primary and secondary data, Mod 43 check character (ANSI/HIBC 2.6 and the HIBCC Mod 43
    appendix);
  - `Udi\IsbtUdi`: ISBT 128 for medical devices, if ICCBBA's specification is reachable, else format only.

  `Udi\UdiFactory::fromString()` detects the agency by the leading characters: `(01)`/`01`/`]` → GS1, `+` → HIBC,
  `=` → ISBT 128. `Udi\BasicUdiDi`: one class per issuing entity (GS1 GMN, HIBCC, ICCBBA, IFA) with that entity's
  check characters (HIBCC: Mod 1021 per its Basic UDI-DI document).
- **NDC:** two classes; both are valid now:
  - `Udi\Ndc`: the current 10 digits in the 4-4-2, 5-3-2 and 5-4-1 configurations. The hyphenated form is required,
    because 10 bare digits fit several configurations; a bare number throws `AmbiguousValueException`. It also offers
    the 11-digit `toBillingFormat()`.
  - `Udi\Ndc12`: the 6-4-2 format of the FDA final rule of 2026-03-05 (91 FR, doc 2026-04368), effective
    2033-03-07.
- **Russian marking (`Marking\RU\`):**
  - `MarkingCode`: the full code with its crypto tail. It accepts every structure the operator (ЦРПТ, «Честный
    знак») publishes, and `structure(): MarkingCodeStructure` names which one. The product group is not decoded: the
    same structure serves several groups. Accessors: `gtin()`, `serial()`, `verificationKey(): ?string` (AI 91),
    `verificationCode(): ?string` (AI 92 / 93).
  - `MarkingIdentifier`: the code without the crypto tail (КИ), as used in documents; `MarkingCode::identifier()`
    returns it.
  - The sources are the Government decrees per product group and the operator's methodology pages on
    markirovka.ru / честныйзнак.рф (the operator is designated by the Government, so its publication counts).
- **EU marking (`Marking\EU\`):**
  - `FmdPackCode`: the unique identifier of Delegated Regulation (EU) 2016/161, as a GS1 element string or as the
    IFA format. `productCode()` returns a GTIN/NTIN or a `Ppn`.
  - `Ppn`: the IFA Pharmacy Product Number, with the check digits from IFA's own specification.
  - `TobaccoUnitIdentifier`: the unit-level UI of Implementing Regulation (EU) 2018/574. Format only, beyond what
    the regulation fixes: length and the time stamp. The rest of the structure is each ID issuer's own.

## Review Focus

1. A GTIN typed as EAN-13 (`4006381333931`), UPC-A (`036000291452`) and GTIN-14 (`04006381333931`): the 13- and
   14-digit forms are one value, and `__toString()` and `format()` follow the quoted GS1 rule.
2. A scanner string with the symbology identifier and raw GS separators (`]d201095060001343521721122510ABC\x1D21XYZ`)
   parses to the same value as its bracketed form, and the round trip keeps a `(` inside a serial.
3. An expiry `YYMMDD` with `DD = 00`, a 29 February in a leap and a non-leap year, and the century window at both
   edges relative to a fixed `$today`.
4. A Russian tobacco pack code (non-AI structure) and a GS1-structured code with AI 91/92: both parse. A code
   with its GS separators lost (copied from a web form) is refused, not silently split in the wrong place.
5. `CurrencyCode::fromNumeric('643')` gives RUB, a numeric code reused by a withdrawn currency gives the current one,
   and an unknown numeric code fails.
